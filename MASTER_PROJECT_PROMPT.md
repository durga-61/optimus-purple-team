# 4. CORE SECURITY CONCEPT

The main security problem is DATA INTEGRITY.

An attacker may change operational values while keeping individual values plausible.

Example:

Total capacity = 50 tons

Inventory = 42 tons

Reported free capacity = 40 tons

Each number individually looks possible.

However:

42 + 40 > 50

Therefore the records are inconsistent.

The system must identify this as a semantic integrity violation.

# 6. SEMANTIC INTEGRITY ENGINE

Implement and preserve semantic constraints.

## C1 - Capacity Consistency

Check:

inventory + free_capacity ≈ total_capacity

Allow a configurable tolerance.

Also consider relevant occupancy/capacity relationships.

---

## C2 - Inventory Flow Consistency

Check:

current inventory ≈ previous inventory + inbound - outbound

Allow realistic tolerance.

---

## C3 - Historical Consistency

Compare current observations against normal historical operating ranges.

Historical information is supporting evidence.

It must not automatically mean an attack occurred.

---

# 7. TEMPORAL ANALYSIS

The system must remember previous security observations.

Evaluate:

* persistence;
* frequency;
* repeated violations;
* recency;
* decay.

A single weak violation may remain suspicious.

Repeated violations should increase the security significance.

The actual temporal values must be displayed in the dashboard.
